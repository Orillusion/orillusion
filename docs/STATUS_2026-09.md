### 每项修了什么

**1. Rapier API 漂移。** 根依赖是 rapier3d-compat 0.19.3，插件按 0.14 写。0.15 起查询管线并入 broad-phase，由 `world.step()` 刷新，`updateSceneQueries()` 被删除。改为调用 0.19 保留的 `propagateModifiedBodyPositionsToColliders()`。用 `grep Physics.world.<method>` 与 `pipeline/world.d.ts` 逐个比对，确认插件其余调用（`castRay`、`createCharacterController`、车辆控制器等）在 0.19 都存在。

**2. 首帧穿地。** 引擎每帧顺序是：组件 `onUpdate` → `renderLoop`（示例在这里调 `Physics.update()`）。角色在创建当帧就 `move()`，此时还没有 `world.step()`，BVH 为空，`computeColliderMovement` 扫不到任何东西，返回完整位移。`Physics` 新增 `stepCount`，控制器记录创建时的 step 数，至少经过一次 step 后才允许移动。

**3. 首帧 delta。** `_tick` 用 `time - Time.time` 算 delta，`Time.time` 初始为 0，第一帧 delta 等于 rAF 时间戳（通常 1–5 秒）；`pause()` 期间 `Time.time` 冻结，`resume()` 第一帧 delta 等于暂停时长。物理、动画、插值器、控制器都会在这一帧跳一大步。加 `_resetDelta` 标记，循环首次启动和 `resume()` 后的第一帧使用 1/60 s。

**4. staging buffer 池。** `mapAsyncWrite` 的 `mapAsyncBuffersOutstanding` 在创建时加、复用时不减，启动阶段 GPU 编译管线导致 `mapAsync` 延迟 20 多帧，池子一次膨胀几十个后永远不缩，计数永远超过阈值，警告每帧触发；`destroy()` 也不释放池内 buffer。现在：计数改为真实在途数（resolve 时递减）；空闲池上限 3 个，多余的在 resolve 时销毁；`destroy()` 释放池并把池置空，让在途的 buffer 自行释放；警告改为每次积压只报一次并带 MB 数，阈值 60；`MatrixGPUBuffer.writeBufferByHeap` 改为委托同一实现，去掉重复代码但保留旧函数名。
